# AssetTrust v0.18 — Security Fix, Release Gates and Kali Guide

**Compiled by: Aturinzire Hargreave**

## Why v0.18 matters

The previous MFA-disable function selected a matching backup-code hash from `auth_recovery_codes`, but did not filter `consumed_at`. The login path *did* filter previously consumed codes. If an attacker obtained the account password and an already used recovery code, the MFA-disable path could accept that used recovery code as the additional factor. This fix makes both paths enforce the same one-time-use rule.

The application still uses 14-character base64url codes based on 10 random bytes, and hashes codes before database storage. Sensitive SQL operations remain bound to the authenticated user and execute under a transaction with an MFA-credential row lock.

## Source changes

- `apps/api/src/contexts/identity/domain/identity-policy.ts`: `isValidRecoveryCode()` pure domain predicate (no NestJS/PostgreSQL imports).
- `apps/api/src/auth.ts`: one-time-use condition on MFA-disable SQL; calls the domain predicate in both MFA completion and disable paths.
- `tools/tests-v18/`: method-execution regression plus domain-predicate tests.
- `tools/e2e-identity-v05.mjs`: three additional HTTP assertions for a disposable PostgreSQL environment (NOT RUN in this workspace).
- `.github/workflows/ci.yml`: runs `verify:v18` after earlier suites.

## On Kali (fresh disposable development environment only)

```bash
unzip AssetTrust_v18_Identity_Recovery_Security_Checkpoint.zip
cd assettrust-v18
npm install
# Review and commit the generated package-lock.json. Never create a dummy lockfile.
npm ci
npm run verify:v18
npm run verify:architecture
npm run verify:syntax
npm run release:gate:v17
npm run build
```

Set real, independent `JWT_SECRET`, `MFA_ENCRYPTION_KEY` and document encryption keys in a private `.env` as described in `.env.example`. Do not put secrets in a Git repository.

For a **fresh disposable database**, start PostGIS using the repo's compose service, run `npm run db:migrate`, then `npm run db:check`. Do not run these fresh-install commands against an existing database: follow `docs/V11_MIGRATION_AND_RELEASE.md` for the backup-gated baseline procedure.

To test the live authentication flow, use the supervised localhost integration command documented in `docs/V15_RUNBOOK.md`, in an explicitly marked test environment. The existing `tools/e2e-identity-v05.mjs` now exercises the v0.18 fix as part of that run. Never run state-mutating integration scripts on production.

## Release blockers

1. Real `package-lock.json` generated by npm and reviewed.
2. Successful `npm ci`, API/web build, and full typechecking.
3. Successful PostGIS migrations, idempotency, and schema checks.
4. Successful disposable HTTP identity, document, professional-verification, and geographic workflow tests.
5. Browser E2E, penetration testing, secret management, operational monitoring, data backups and restore exercises.
6. Authorized government, payments, professional licensing, and blockchain integrations must not be represented as live until approved and tested.

**Release decision: BLOCKED.** This checkpoint does not make an official land registry or title-verification system.
